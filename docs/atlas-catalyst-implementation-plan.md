# Atlas → Catalyst Implementation Plan

## Goals
- Use Atlas agents to generate educational content that conforms to Catalyst's Golden Format schema.
- Automate data entry into the legacy Catalyst UI (no API dependency), with auditability and safe human approvals.
- Start narrow (one lesson type + few task types), then scale to full schema support.

## 1) System Architecture

### Agents
1. **Project Manager Agent (Orchestrator)**
   - Owns workflow state and task routing.
   - Validates contract handoffs and blocks invalid transitions.
2. **Content Expert Agent**
   - Generates pedagogically aligned lesson structures and task copy.
   - Produces a schema-shaped draft (`lesson_plan_draft.json`) and media requirements.
3. **Media Asset Generator Agent**
   - Produces image/audio/video assets and required metadata (`assetId`, `alt`, `transcript`, `subtitlesUrl`).
   - Returns an `asset_manifest.json` consumable by Content + Entry agents.
4. **Content Entry Agent (UI Automation)**
   - Logs into Catalyst and fills template fields deterministically.
   - Uploads assets and performs preview/publish checks.

### Supporting Services
- **Schema Validator Service**: validates all artifacts against Golden Format constraints.
- **Artifact Store**: stores JSON versions, generated media, automation logs, screenshots.
- **Run Ledger**: immutable per-job timeline for compliance and rollback.

## 2) Workflow and State Machine

`brief_received` → `outline_ready` → `content_draft_ready` → `schema_validated` → `assets_generated` → `entry_ready` → `entered_in_catalyst` → `qa_passed` → `published`

### Failure / retry states
- `schema_failed`: validation errors; returns to Content Expert.
- `asset_failed`: missing/transcode/metadata issues; returns to Media Generator.
- `ui_automation_failed`: selector drift/session timeout; retries then escalation.

### Human gates
- Editorial approval before `entry_ready`.
- Final QA approval before `published`.

## 3) Data Contracts Between Agents

## A. Brief Package (`brief.json`)
- `jobId`, `audience`, `targetLocale`, `instructionsLocale`, `learningObjectives`, `deadline`, `templateType`.
- Constrain locales to Catalyst enum (e.g., `en_US`, `es_ES`, `ja_JP`).

## B. Content Draft (`lesson_plan_draft.json`)
Generated by Content Expert in Golden-Format shape (subset for MVP):
- `LessonPlanInfo`: `id`, `title`, `description`, `shortDescription`, `availableInstructionsLocales`, `instructionsLocale`.
- `LessonPlan`: `type` (`self-study` first), `targetLocale`, `contentType`, `content`, `schemaVersion=1`.
- `contentType` MVP: `with-steps`.
- `content.steps[].activities[].tasks[]` as `TaskWrapper` objects.

## C. Asset Requirements (`asset_requirements.json`)
Per referenced `Stimulus` needing generation:
- `stimulusId`, `stimulusType` (`image`, `audio`, `video`, `image-audio`),
- creative brief, dimensions/duration, locale, transcript/subtitles requirements,
- acceptance criteria.

## D. Asset Manifest (`asset_manifest.json`)
- maps each `stimulusId` to final fields expected by schema:
  - image: `title`, `url`, `assetId`, `alt`
  - audio: `title`, `url`, `assetId`, `alt`, `transcript`
  - video: `title`, `url`, `assetId`, `alt`, `subtitlesUrl`, `transcript` (for stimulus video)

## E. Entry Package (`entry_package.json`)
- Fully merged lesson plan payload + media manifest + Catalyst template mapping ID.
- Includes deterministic write plan: ordered list of UI actions and expected field values.

## 4) MVP Scope (First Release)

To de-risk quickly, support only:
- `LessonPlanType`: `self-study`
- `LessonPlanContentType`: `with-steps`
- Representative Catalyst templates / task types:
  - **Multiple Select** (`taskType=multiple-choice` with `allowMultipleSelect=true`)
  - **Gap Fill** (`taskType=gapfill`)
  - **Categorization** (`taskType=categorisation`)
- Stimulus types:
  - `plain-text`
  - `image`
  - `audio`

Everything else is marked `not_supported_yet` with clear rejection reasons.

### Template-specific authoring contracts

#### A. Multiple Select (`multiple-choice`)
- Task-level mapping:
  - `prompt` ← Task Prompt field
  - `interactionType` ← Interaction Type (`tap` for MVP)
  - `feedbackScope` ← Feedback Scope dropdown
  - `feedbackMode` ← Feedback Mode dropdown
  - `allowMultipleSelect=true` when Answer Type is set to Multiple
  - `displayOptionsInline`, `showSequenceNumbers`, `randomiseResponseOptions` ← checkbox controls
- Options mapping:
  - each answer option row maps to `task.multipleChoice.responseOptions[]`
  - correctness maps to `expectedResponse.contents.multipleChoice.contents[optionId].userInput=selected` for correct options

#### B. Gap Fill (`gapfill`)
- Use `task.gapfill.sections[]` with sentence-level `GapfillItems` for MVP.
- Each gap item must include:
  - `id`
  - `gapType` (`selection` for dropdown style or `text` for free entry)
  - `options[]` (required by schema, even for text gaps with a canonical expected value)
- Correct answers map to `expectedResponse.contents.gapfill[gapId].userInput`.

#### C. Categorization (`categorisation`)
- Author categories in `task.categorisation.targets[]`.
- Author draggable/selectable items in `task.categorisation.options[]`.
- Control shuffle behavior with `randomOrder`.
- Correct mapping stored in `expectedResponse.contents.categorisation[itemId].userInput=<targetId>`.

## 5) Validation Rules to Implement Early

1. **Required-field completeness** for all authored nodes.
2. **Enum enforcement** (`Locale`, `TaskType`, `FeedbackScope`, `SubmissionScope`, etc.).
3. **Cross-field logic**:
   - `taskType` must match populated `task.<variant>` and `expectedResponse.type`.
   - `submissionScope` must be same or coarser granularity than `feedbackScope`.
   - for multiple select, `allowMultipleSelect=true` must allow more than one selected correct option.
   - for categorization, every option must map to exactly one valid target ID.
   - for gap fill, every gap ID must exist in authored sections and have exactly one expected response.
   - media stimuli must include required metadata fields.
4. **ID integrity**:
   - unique IDs for lesson/steps/activities/tasks/stimuli.
   - `TaskResponse.taskId` must match `TaskWrapper.id`.
5. **Pedagogical linting** (custom):
   - minimum instruction clarity,
   - locale consistency for target/instructions,
   - no empty activity/task arrays.

## 6) Catalyst UI Automation Strategy

### Approach
- Use robust browser automation with:
  - page objects per Catalyst template screen,
  - stable selectors (prefer labels/data attributes; fallback xpath only where unavoidable),
  - typed input adapters for each field family (text, rich text, list rows, media upload, task options).

### Resilience patterns
- Save-after-each-section checkpoints.
- Screenshot + HTML snapshot on failure.
- Idempotent rerun support (detect existing draft by external `jobId`).

### Output artifacts
- `entry_log.json` (every field write + timestamp + status),
- `entry_screenshots/`,
- `publish_result.json` (draft/published URL, Catalyst internal ID, version).

## 7) RACI (Who owns what)
- **PM Agent**: orchestration, SLA tracking, escalation.
- **Content Expert**: instructional quality + schema-compliant authoring.
- **Media Agent**: assets and accessibility metadata quality.
- **Entry Agent**: CMS correctness and publish execution.
- **Human editor**: quality gate + exception handling.

## 8) Milestone Plan

### Milestone 1 (2 weeks): Contract + Validator
- Define JSON schemas for all handoffs.
- Build validator with rich error messages and auto-fix hints.

### Milestone 2 (2 weeks): Content + Media MVP
- Content Expert supports MVP task types.
- Media Generator supports image/audio with metadata completeness checks.

### Milestone 3 (2 weeks): Catalyst automation MVP
- End-to-end entry for one template.
- Publish dry-run environment with logs/screenshots.

### Milestone 4 (2 weeks): Hardening
- Retry policies, drift detection, monitoring dashboard, human review UI.
